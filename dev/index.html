AT25040B Driver¶

A C++20 driver for the Microchip (formerly Atmel) AT25010B, AT25020B and AT25040B SPI serial EEPROMs. It checks that a chip really answers before trusting it, reads any range, writes page by page with the write enable latch, the write cycle and a read-back checked at every step, drives the WP pin and sets the block protection, on any MCU.

Quickstart API guide Source on GitHub

The AT25040B is a 1 Kbit, 2 Kbit or 4 Kbit serial EEPROM (128, 256 or 512 bytes) on an SPI bus: it keeps data with the power off, writes a page in one self-timed cycle and protects a quarter, a half or all of the array (Features, p. 1).

Quick start¶

Wire the chip as above, write the port for your MCU (Porting), then:

#include <array>
#include <cstdint>

#include "at25040b.hpp"

int read_board_id(MyPort& port, std::array<uint8_t, 8>& id) {
  at25040b::AT25040B<MyPort> eeprom(port); // AT25040B, identity check on; no I/O yet

  if (auto r = eeprom.EnsureInitialized(); !r) { // 1. bus up, identity check
    return static_cast<int>(r.error); //    NoDevice: nothing on MISO. DeviceIdMismatch: wiring, WP
  }
  if (auto r = eeprom.Read(0, id); !r) { // 2. eight bytes from address 0
    return static_cast<int>(r.error);    //    Timeout: a write cycle that never ends
  }
  return 0; // 3. id holds what the chip sent: one READ, so check its CRC
}

From docs/hardware.yml; kokeb-docs hardware --check confirms that every API name is in inc/at25040b.hpp, inc/at25040b_types.hpp, inc/at25040b_spi_interface.hpp and every register in inc/at25040b_registers.hpp.

The driver has no platform code. You give it a small class that brings the bus up, moves bytes and waits; it does the rest: the identity check, the instruction framing with A8, the page split, the write cycle, the WP pin and the checks that catch a dead or noisy bus.

What you get¶

  • One object per chip. AT25040B<YourPort> takes a reference to your port and does no I/O until EnsureInitialized(). See API guide.
  • A probe that a dead bus cannot pass. The start-up check reads the status twice and toggles the write enable latch, so a floating, stuck or echoing MISO fails it. See Contract.
  • Writes you can trust. Page split, WREN per page, WEN checked, the write cycle waited for, each page read back. See API guide.
  • Errors you can act on. Every call returns Result<T> with an Error such as NoDevice, BusNoise or WriteProtected. See API guide.
  • No heap, no exceptions, no RTTI. The host tests build with -fno-exceptions -fno-rtti. See Contract.
  • Tested without hardware. Host tests and a fuzzer run the driver against a protocol model of the chip. See Testing and CI. Not yet verified on hardware: Status and limitations.
