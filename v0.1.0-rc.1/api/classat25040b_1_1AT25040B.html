Detailed Description

template<SpiPort Port>
class at25040b::AT25040B< Port >

Driver for one AT25010B, AT25020B or AT25040B on a platform port.

Lifecycle: construct with the configuration (no I/O), then EnsureInitialized(), the one way to start (bus up, identity check), use, optionally Deinitialize(). Every call that touches the chip returns Error::NotInitialized until EnsureInitialized() has succeeded; no call starts the chip as a side effect, so a probe happens only when you ask for it.

Every call that reads or writes the array first reads the status and, if a write cycle runs, waits for it (at most Config::write_timeout_us): it never sends an instruction the chip would ignore. Every write and every block-protection change waits for its own write cycle before it returns, so the next call finds the chip ready.

Optional port hooks, found at compile time:

Hook Used for Without it
bool GpioSet(CtrlPin, GpioSignal) noexcept WP: released (high) only while a write, a block-protection change or the identity check runs; parked (low) after, on success and failure WP must be tied high for writes (or low, read-only: set Config::check_write_enable = false)
void Log(LogLevel, const char* message) noexcept One line per lifecycle event or failure Nothing is logged

A hook declared with the wrong signature (for example void GpioSet(...)) is a compile error. The driver never drives HOLD: tie it high (a HOLD strapped to CS makes every status read fail).

Leave the chip safe and mark the driver uninitialised: WRDI, then WP parked.

The driver is uninitialised afterwards even if a step failed; the next EnsureInitialized() runs the identity check again, which is how a handler probes the chip again. On an uninitialised driver it does nothing and returns Ok.

◆ EnsureInitialized()

template<SpiPort Port>
Result< void > at25040b::AT25040B< Port >::EnsureInitialized ( )
noexcept

Check that an AT25xxxB answers, once: the only way to initialise the driver.

Brings the bus up, parks WP (with GpioSet()), then checks the identity, strongest test first: the status is read until it is not busy (a write cycle may still run after an MCU reset), then once more, and both reads must be the same idle status (bits 7 to 4 and RDY clear). With Config::check_write_enable (the default) it then releases WP, clears the latch if it was set (WRDI), sends WREN and reads WEN = 1, sends WRDI and reads WEN = 0, and parks WP: a bus whose MISO floats or is stuck cannot pass this, and nothing is programmed. Without it, the first kIdentityReadBytes are read twice and must be equal. After it succeeds, later calls return Ok at once with no I/O; after it fails, the next call starts again from the beginning.

Returns
Ok, InvalidArgument (the configuration fails Validate(); no I/O), Bus, Pin (the WP hook failed), NoDevice (status 0xFF throughout Config::write_timeout_us), DeviceIdMismatch or BusNoise.

Read out.size() bytes from address (sequential READ, section 6, "Read Sequence").

Waits for a running write cycle first (two status reads on an idle chip: the idle status is confirmed). The read is split into transfers of at most kReadChunkBytes data bytes. With Verify::None each is read once: 2 + ceil(n / 16) transfers for n bytes. With Verify::ReadBack each is read twice and compared (BusNoise): 2 + 2 x ceil(n / 16) transfers, twice the bus time. The range never wraps: the chip would roll over to address 0, the driver refuses.

Parameters
addressFirst address, below GetCapacityBytes().
outWhere the bytes go: at least 1 byte, address + out.size() at most GetCapacityBytes(). A std::array or a C array converts to it.
verifyVerify::None (the default) or Verify::ReadBack.
Returns
Ok, NotInitialized, InvalidArgument (empty or out-of-range, or verify not an enumerator; nothing sent, out untouched), Bus, Timeout or BusNoise. After a failure past the argument checks, every byte of out is 0: no partial data is left behind.

Read the status register once: one RDSR transfer, no wait, no retry, no decoding and no check of the byte (handbook KB-CPP-129).

For bring-up and diagnostics. RDSR has no side effect on the chip (section 6, "Read Status Register") and works during a write cycle (it then reads 0xFF). The byte is also kept for GetLastStatusByte().

Write data from address: one WRITE and one write cycle per 8-byte page.

Reads the status first and refuses a range that overlaps the block-protected part (BlockProtected) before sending anything else. Then, with WP released: per page WREN, a status read that must show WEN = 1 (WriteProtected otherwise), the WRITE, a wait for the write cycle (Timeout after Config::write_timeout_us), a status that must show WEN = 0 again (WriteMismatch when the chip ignored the WRITE; this reuses the last poll, no extra transfer) and, with Verify::ReadBack, a read back (WriteMismatch). WP is parked after, on success and failure; a failure after WREN sends WRDI, so the latch is not left set.

Cost with Verify::None: 2 status reads, then per page WREN, RDSR, WRITE and the status polls of the write cycle (at least 2: the idle status is confirmed), so 2 + 5 x pages transfers plus one RDSR per extra 100 µs poll. Verify::ReadBack adds one READ per page.

After a failure, the pages before the failing one hold the new data (and were read back, with Verify::ReadBack); the failing page may hold old, new or, after a failed WRITE transfer, partly written data; nothing after it and nothing outside the range is touched.

Parameters
addressFirst address, below GetCapacityBytes().
dataThe bytes to write: at least 1, address + data.size() at most GetCapacityBytes(). A std::array or a C array converts to it.
verifyVerify::None (the default) or Verify::ReadBack.
Returns
Ok, NotInitialized, InvalidArgument (nothing sent; also for a verify that is not an enumerator), Bus, Pin (the WP hook failed), Timeout, BusNoise, BlockProtected, WriteProtected or WriteMismatch.
